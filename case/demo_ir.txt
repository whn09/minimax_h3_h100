# SYNTHETIC IR CASES. These are the fixture the `ir/` package compiles against, validates, and uses
# as few-shots. They are written, not harvested: every number in PROMPT_IR.md and every rule in
# validate.py was measured on a customer's prompt, which is not in this repo and will not be. Treat
# this file as the SHAPE of a working H3 IR, not as a reproduction of any measurement.
#
# WHY A FILE AND NOT A PYTHON LITERAL. `ir/h3ir/guides.py:golds()` reads it at runtime for the
# few-shots and `ir/tests/test_validate.py` reads it as the end-to-end fixture, so the two cannot
# drift apart. One case per LINE; `\n` is decoded to a real newline by `scripts/sglang_case.py`
# (the format needs blank lines, so the two cannot both be literal); a ref2va line ends with the
# reference-image filename, resolved against refdir=.
#
# THE FORMAT IS THE OFFICIAL ONE, documented here because the system that emits it is not open:
# SGLang feeds this text to Qwen3-VL verbatim (presentation.py:109 -- no chat template, no
# rewriter), while MiniMax's product first runs the input through H3-Context-IR, a hosted
# multi-stage rewriter the release excludes. So whatever you send IS the IR, and a one-sentence
# prompt is an out-of-distribution input rather than a short one. That is the whole premise of the
# `ir/` package. ref2va takes SIX blank-line-separated sections:
#     subject_definitions / summary / retention_analysis / detailed_description /
#     overall_soundscape / non_diegetic_music
# t2va takes THREE:
#     integrated_multimodal_description / overall_soundscape / non_diegetic_music
# with every asset labelled (`<Subject N>` reusable content, `<Picture N>` frame anchor), a
# bracketed task prefix on the ref2va summary, one of fully_preserved / partially_preserved /
# attribute_transfer / weak_reference per label, and 350-500 English words of detailed_description.
# Only dialogue (inside `<d>` with a language tag) and on-screen text (inside "double quotes") are
# ever non-English. PROMPT_IR.md sec. 4 derives all 36 rules.
#
# THE t2va LINE IS DELIBERATELY DEFECTIVE, and the test suite depends on it staying that way. Its
# dialogue contains `2L`, a digit welded to a letter, which is the one defect we measured that
# NEITHER official guide mentions and that MiniMax's own hosted IR does not fix either: such a token
# has no grapheme-to-phoneme path and the TTS voices it as noise. So
# `test_case_ir_t2va_is_rejected_for_the_measured_mixed_script_defect` asserts this line fails on
# exactly E030-D-MIXED-SCRIPT-TOKEN and nothing else, while `golds()` hands the model the REPAIRED
# form (`2L` -> `两升`) as the few-shot. One line, both roles: the negative example for the
# validator and the positive example for the compiler.
